## SQA-04：模型流式读取与结束状态

- **目标：** 实现可注入、可逐段读取的模型适配，明确空增量、正常结束、长度截断、空回答、异常结束及关闭上游流的处理；保留旧的非流式模型调用。
- **预计涉及：** [`qa.py`](../../../backend/app/services/qa.py)、[`config.py`](../../../backend/app/core/config.py)、对应后端测试；如需拆分文件以最终职责划分为准。
- **学习重点：** 流中每段不是完整回答；创建模型请求和迭代响应都可能失败；有效正常结束与 HTTP 连接结束不是一回事。
- **验收：** 受控模拟覆盖增量顺序、空片段、正常与长度结束、空回答、无法识别的结束状态、调用及迭代异常、上游资源释放。首个有效文字前的纯空白暂存，有效文字到达时保持原序合并为一个 `delta` 发送；失败重试时丢弃该次未发送的暂存，只有空白则为空回答。合法但未知的模型结束原因转为通用未完成；上游没有有效结束原因就断开不能伪造成功。流式空回答视为未完成，旧接口不因此改变。检查 Python 3.10+ 与项目未锁定的 SDK 版本范围，避免假设异步接口和关闭方式都已验证。
- **结果与证据：** 新增 `AsyncDeepSeekClient.stream_answer()`，单次异步读取模型增量，输出内部 `delta`、`done` 或 `incomplete`，并负责上游流清理；该内部 `done` 不含来源，后续 SSE 路由负责正常完成时组装来源。调用方如提前退出须显式关闭生成器。新增受控流测试 18 项，包括异常、提前关闭、取消发生在关闭期间、空白边界和连续两次单次尝试之间的暂存隔离；以 OpenAI SDK 3.8.0 与 `httpx.MockTransport` 在内存中验证 SDK 解析，未访问真实提供方。在 `backend/` 以 Python 3.14.6 执行 `python -B -m unittest discover -s tests -p 'test_qa*.py'`（71/71 PASS，含旧问答 53 项与新增流测试 18 项）及 `python -B -m unittest discover -s tests -p test_query.py`（11/11 PASS）；`git diff --check` PASS。后端空白集合与本机 Node `trim()` 的 BMP 范围对照一致；未验证其他浏览器、Python 版本或仓库声明的最低 OpenAI SDK 1.1.0。独立审查发现的取消清理和空白判定问题已修复并复测。自动重试、整体超时、真实 HTTP 断连及 SSE 路由归 SQA-05/06/09，不视为已实现或验证。

## SQA-05：流式 API 和事件发送

- **目标：** 在保留 `POST /api/query` 的同时增加 `POST /api/query/stream`；请求体沿用 `question`、`collection_name`、可选 `top_k` 与 `history`。输出 `status`、`delta`、`done`、`incomplete`、`error`；正常 `done` 携带来源。
- **预计涉及：** [`query.py`](../../../backend/app/api/query.py)、[`router.py`](../../../backend/app/api/router.py)、[`schemas.py`](../../../backend/app/models/schemas.py)、[`main.py`](../../../backend/app/main.py) 与对应后端测试。
- **学习重点：** 流响应头发送前后的错误如何区分；检索发生在已开始的流中，因此检索异常需要通过事件报告；用户停止或断线不保证能收到终止事件。
- **验收：** 基础参数、知识库不存在和空库在流开始前保留现有 JSON 错误合同；流开始后状态与增量有序，仅在后端确认上游正常结束且回答非空白后发送 `done` 并携带来源；截断、空回答和失败不作为成功；非空库无命中继续调用模型且来源为空。`status.stage`、`delta.text`、`done.sources`、`incomplete.reason`、`error.code/message` 为必要字段，来源沿用现有四字段；`sources=[]` 有效。受控注入 `QUERY_TIMEOUT` 时，验证流前映射 HTTP 504、流内映射同码 `error`；实际四分钟期限的计时、触发和取消由 SQA-06 实施验证，不将本任务的错误映射测试描述为计时已实现。其他具体实现与规格对齐。
- **结果与证据：** 新增 `POST /api/query/stream`：流前校验参数、知识库和空库，流内按事件发送状态、文字、结果与经过清理的错误；正常 `done` 保留全部检索来源。新增 `QUERY_TIMEOUT` 错误目录映射，限于受控注入测试，尚未实现实际四分钟计时。修复 ASGI 发送失败及 AnyIO 取消下的响应/上游流关闭；流内模型不可用提示不再错误声称已重试，旧接口提示不变。在 `backend/` 使用 Python 3.14.6 执行 `python -B -m unittest discover -s tests -p 'test_qa*.py'`（71/71 PASS）与 `python -B -m unittest discover -s tests -p 'test_query*.py'`（33/33 PASS，其中新增流路由 22 项）；`git diff --check` PASS。测试使用真实 FastAPI 路由与受控存储/模型及模拟 ASGI 2.0/2.4，不能证明真实本地 HTTP 逐段到达、真实断连或提供方行为。独立复核发现的清理、编码和提示问题已修复并复测；SDK 最低版本、真实服务、实际总时限与重试仍待 SQA-06/09/10 验证。

## SQA-06：后端重试、超时、取消和资源清理

- **目标：** 实现已确认策略：默认最多 2 次自动重试、等待 1 秒和 2 秒；重试复用本次检索结果，只在发送任何非空回答 `delta` 前发生。整次问答初始上限为 4 分钟，包含检索、自动重试和生成。
- **预计涉及：** 流式模型与路由实现、[`config.py`](../../../backend/app/core/config.py) 和后端测试；与前端的计时和取消约定需一致。
- **学习重点：** 网络读写超时与总体时限不同；SDK 自身重试与应用层重试不能叠加；取消是协作过程，同步线程和外部提供方可能不会立即停止。
- **验收：** 验证初次及读取首段前失败、1/2 秒等待、总次数和重试耗尽；首个有效文字前暂存纯空白，在可恢复失败后可重试并丢弃该次暂存，首段有效文字与暂存合并为一个 `delta` 原序发送；已发送非空回答后不自动重试；认证、配置和无效请求不做无意义重试。覆盖检索、等待、生成时停止和整体超时：不再安排后续重试，检索返回后检查取消并避免继续发起模型请求，尽力释放上游流。后端整体超时的 `QUERY_TIMEOUT` 在流前映射 HTTP 504、流内映射 `error`；客户端断开、心跳、超时与正常完成竞争均有明确终态；断开或外部计费停止不作无法保证的承诺。
- **结果与证据：** 后端对可恢复且首段文字尚未发出的模型错误按 `LLM_MAX_RETRIES`（限制在 0–2 次）重试，间隔 1 秒和 2 秒；复用检索结果，SDK 自身重试为 0，清理失败时不重试。流式路由在读取请求体之前开始计算单调时钟期限，`STREAM_QUERY_TIMEOUT` 默认 240 秒；期限覆盖前置检查、检索、模型读取、等待和发送，前端从提交计时仍待 SQA-07 实现。响应已开始且连接可写时以 `error` 报告超时；发送阻塞或客户端断开时只能尽力通知和清理，后台同步工作及外部提供方不保证立即停止。ASGI 2.4 也主动监听断连。以 Python 3.14.6 在 `backend/` 执行 `python -B -m unittest discover -s tests -p 'test_qa*.py'`（76/76）和 `python -B -m unittest discover -s tests -p 'test_query*.py'`（51/51，其中本任务新增控制测试 18 项），均通过。测试使用真实 FastAPI 路由、真实模型适配器与受控 ASGI、存储和 SDK：覆盖重试次数/间隔、首字前后屏障、请求体/前置检查/检索/等待/模型及发送阻塞的实际短期限、延迟终态判定、受阻清理以及 ASGI 2.4 三阶段断连。独立复核发现并复现的断连监听问题已修复并通过受控复测。未验证真实本地 HTTP、真实 DeepSeek、Python 3.10 或最低 SDK 版本；完整浏览器交互和竞态验收仍属 SQA-07～10。

## SQA-07：前端流式读取与事件解析

- **目标：** 保留旧 `queryQA`，新增 `POST /api/query/stream` 流式读取，沿用请求字段并校验 HTTP 和事件数据，按已确认协议分发事件。
- **预计涉及：** [`api-client.ts`](../../../frontend/lib/api-client.ts)、[`types.ts`](../../../frontend/lib/types.ts)、必要的解析测试。
- **学习重点：** 网络数据块不是事件边界；UTF-8 字符可跨块；SSE 帧、JSON 值和业务事件是不同层次。区分用户取消、超时、HTTP 错误、流内错误及无终止事件的断流。
- **验收：** 可控字节流覆盖中文跨块、事件拆分和合并、换行与注释、字段校验、非法数据和提前 EOF；实际前端空白判定与 SQA-04 的 ECMAScript `trim()` 集合一致。未知事件类型忽略，已知事件必要字段有效时忽略额外字段；已知事件 JSON 或必要字段无效、累计回答为空白却收到 `done` 均触发前端本地 `STREAM_PROTOCOL_ERROR`；未知但合法的 `stage` 显示通用处理中，未知但合法的 `incomplete.reason` 显示通用未完成。只有有效的正常完成才能成功；流前 HTTP 504、流内 `QUERY_TIMEOUT` 与前端本地 4 分钟超时均显示超时；取消和四分钟期限生效且前端不自动重复整次请求。旧 JSON 客户端回归通过。
- **结果与证据：** 新增 `streamQueryQA`：按 UTF-8 字节流增量解码、按 SSE 行组帧并校验已知事件，通过回调交付事件；有效 `done`、`incomplete`、`error` 为终态，缺少有效终态的 EOF 判为中断。允许调用方传入取消信号和以 `Date.now()` 为基准的提交时刻 `startedAt`；不传时从调用开始计时。处理中止、失败及终态前检查实际期限，已接受的终态不被后续取消覆盖。正常和未完成状态的具体页面提示及展示由 SQA-08 实现。Node 24.18.0 下 `node scripts/verify_stream_query.cjs` 共 21/21 组通过，包括字节/帧拆分、未知与非法数据、旧接口、错误体阻塞、取消、短期限与迟到事件；`npx tsc --noEmit --incremental false` 通过。现有组件模拟回归 `node scripts/verify_f6_integration.cjs` 5/5 和 `node scripts/verify_t1204_contracts.cjs` 2/2 通过。上述为 Node 和受控模拟，不代表真实浏览器或真实 HTTP；`node scripts/verify_frontend_ui.cjs` 因环境缺少 `playwright` 未能启动。独立只读复核未发现其他明确阻塞问题。`Date.now()` 会受系统时钟调整影响；前端真实页面、浏览器兼容、联调及构建验收仍待 SQA-08～10。

## SQA-08：问答状态、历史、草稿和交互

- **目标：** 页面逐段展示、状态提示、停止、最新未完成轮的重新生成、错误和截断；完成后显示来源。保留整个当前会话的可见记录，模型请求只携带最近 20 条已完成消息。
- **预计涉及：** [`QAPanel.tsx`](../../../frontend/components/QAPanel.tsx)、[`page.tsx`](../../../frontend/app/page.tsx)、[`globals.css`](../../../frontend/app/globals.css)、相关前端测试。
- **学习重点：** 显示记录、模型历史、当前请求和下一问题草稿的不同职责；请求身份和终态如何避免过期事件、计时器和清理逻辑污染新请求。
- **验收：** 生成期间允许编辑但禁止发送；停止、失败、截断保留部分且不进入历史、不显示来源；点击重试时立即清除旧部分，首字前新请求停止、失败或超时不恢复旧内容，保留原问题与下一问题草稿。有效新问题通过前端校验并提交即成为最新轮，即使后端立即返回错误旧轮重试也不可用；输入校验失败不创建新轮。发给模型的历史按时间顺序从已完成轮次中提取最近 20 条消息，当前问题单独放在 `question`。切库停止并清空，切换应用内其他页面继续生成、返回查看；首次文字前停止不显示空助手回答。用户向上滚动时不被强制拉回，返回底部恢复跟随，并检查状态提示及无障碍播报。
- **结果与证据：** 问答页面按轮次保留可见对话，仅从完成轮次提取最近 20 条模型历史；接入流式状态、逐段文字、完成后来源、停止和最新未完成轮的重新生成，保留生成期间草稿。切库中止并隔离旧请求；功能页切换保留挂载及后台生成；增加滚动跟随与独立状态播报。隔离预览 API 新增模拟 SSE，并更新既有组件及浏览器回归脚本。以 Node 24.18.0 在 `frontend/` 执行 `node scripts/verify_stream_qa_ui.cjs`（13/13，真实组件与受控 hooks/API/滚动元素）、`node scripts/verify_stream_query.cjs`（21/21，受控字节流）、`node scripts/verify_preview_stream.cjs`（5/5，内存请求/响应）和 `node scripts/verify_f6_integration.cjs`（5/5，受控组件及 API），均通过；`npx tsc --noEmit --incremental false` 与 `npm run build` 通过。浏览器自动化入口启动时缺少运行资源，现有 Playwright 脚本因环境缺少 Playwright 未执行；脚本已更新并通过语法检查，实际浏览器中布局、滚动、状态播报和真实 HTTP 竞态仍需 SQA-09 验证。未使用真实知识库、提供方或用户文件。
