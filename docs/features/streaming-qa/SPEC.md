# 流式回答功能规格（草稿）

> **状态：已实现并经虚构资料联调；真实文档、辅助技术及部分环境仍待验证。** 本文记录截至 2026-11-25 已共同确认的产品行为、接口方向及验证限制。任务进度和证据类型见 [TASKS.md](TASKS.md)；项目通用入口见 [共享开发指南](../../DEVELOPMENT.md)。

## 1. 目标与范围

用户向知识库提问后，前端在检索结束、模型开始输出时逐段显示回答；正常完成后展示来源。用户可以停止生成、重新生成未完成的最新回答、继续多轮对话。维持既有知识库隔离、检索行为以及原非流式 API 兼容。

流式输出改善生成阶段的等待体验，不保证首字、检索或完整回答更快。源文档和向量仍在本地；生成时问题、历史和检索上下文发送给 DeepSeek。V1 无认证授权，仍面向本地或可信网络。密钥只由后端配置提供，不进入前端、源码或日志。

**不在本次范围：** 改变检索算法、权重、阈值或来源语义；服务端会话持久化；跨知识库恢复会话；自动续写截断回答；提高模型输出上限；将实验分支成果视为已合入。若实现中需要更改这些行为，应另行讨论。

## 2. 当前基线

- 现有 [`POST /api/query`](../../../backend/app/api/query.py) 返回完整 JSON；[前端 API 客户端](../../../frontend/lib/api-client.ts) 使用 `response.json()` 等待完整响应。[DeepSeek 调用](../../../backend/app/services/qa.py) 为 `stream=False`。
- [QAService](../../../backend/app/services/qa.py) 先区分空库、混合检索和组装上下文，再生成回答及组装来源。空库报错；非空库但无相关检索结果时继续调用模型、来源为空。
- 当前页面使用同一个 `history` 数组显示消息和构造模型历史，切库使用版本号忽略旧响应而未取消网络请求。发送历史最多 20 **条消息**，不是 20 轮；页面当前也只显示最近 20 条。
- 上下文按片段拼接并受默认 4000 字符上限限制；来源来自全部检索结果。因此来源列表的每项不一定进入模型上下文，也不证明模型实际使用了该项。`file_id` 是文件身份，`chunk_id` 是片段身份。
- 现有非流式测试允许空回答；流式路径的空回答行为不能静默改变原接口。SDK 超时默认 60 秒，应用层默认最多重试两次，间隔 1 秒和 2 秒；SDK 自身重试为 0。60 秒不是整次问答的总时限。

## 3. 已确认的产品行为

### 3.1 正常回答与来源

提交后区分“正在检索资料”和“正在生成回答”；自动重试时明确提示。收到模型文字后逐段显示，使用现有 Markdown 能力。正常完成后才显示来源；无来源不显示空来源列表。回答完成后允许继续提问。

### 3.2 停止、失败与重新生成

| 场景 | 页面与后续历史 |
| --- | --- |
| 尚无文字时停止 | 保留问题并标记已停止，不显示空助手回答；本轮不进入历史。 |
| 已有文字时停止 | 保留已显示部分，标记已停止、未完成；本轮不进入历史。 |
| 生成中失败或连接中断 | 保留问题和已有部分，明确标记失败；本轮不进入历史。 |
| 模型达到长度限制 | 保留内容并标记截断；本轮不进入历史，提供重新生成。 |
| 模型结束但回答为空 | 提示回答为空、视为未完成，不进入历史，提供重新生成。 |
| 重新生成最新未完成轮次 | 保留原问题；点击时立即清除旧的部分回答并手动重新检索。新请求在首字前再次停止、失败或超时时不恢复旧内容；输入框中的下一问题草稿保留。 |

未完成轮次不显示来源。只有最新一轮未完成时可重新生成；有效新问题通过前端校验并提交时即创建新轮、旧轮重试入口不可用，即使新轮随后在流前失败；旧内容仍可见。前端校验未通过（如问题为空）不创建新轮，旧轮仍可重试。重新生成是新请求，可能得到不同内容或来源；不保证截断不再发生。若网络断开未收到终止事件，不能判定成功。

### 3.3 对话、草稿与导航

- 页面保留当前知识库会话的全部可见记录，包括未完成内容；刷新或切换知识库时清空。发送给模型的历史先按时间顺序选取已完成轮次的 `user` / `assistant` 消息，再取最近 20 条；当前问题单独放在 `question`，不重复放入历史。
- 生成中可编辑下一个问题，但当前回答结束、停止或失败前不可发送。停止、失败和重新生成均保留该草稿；发送或切换知识库后清空。
- 切换知识库时停止旧生成并清空对话和草稿；旧事件不得写入新会话。切换应用内其他功能页时继续生成，返回后展示真实进度、结果或错误，不额外提醒。刷新、关闭页面或断网不保证后台继续。
- 用户向上滚动阅读时暂停自动跟随；回到底部后恢复跟随。

### 3.4 知识库边界

- 知识库存在但没有文档：不调用模型，提示先上传，保留问题供重试；切换至上传页面再返回后，若仍在同一知识库且该问题仍为最新轮，应能重试。
- 知识库有文档但无相关检索结果：沿用当前空上下文调用模型的行为，提示词要求说明资料不足，正常完成后来源为空。提示词不能保证模型必然遵守；真实联调须如实观察。

## 4. 已确认的接口方向与错误边界

保留原 `POST /api/query` 完整 JSON 合同，新增独立 `POST /api/query/stream`，浏览器通过 `fetch` 读取 SSE，不改变原接口行为。请求体沿用 `question`、`collection_name`、可选 `top_k` 和 `history`，保持现有校验与身份语义；当前问题与已完成历史按第 3.3 节分别传入。

流开始前完成请求参数、知识库存在和空库检查；失败按现有 HTTP 错误格式返回，包括无效请求 400、不存在 404、空库 409。流开始后执行检索、模型请求和输出；错误尽可能以流内 `error` 表达。HTTP 200 仅表示流建立，不代表问答完成。网络断开时事件可能无法送达，前端以无有效终止事件结束识别中断。

## 5. 已确认的事件设计

事件类型及以下最小字段合同已确认；后端发送链路、前端事件解析和页面接入已实现，并使用隔离的虚构资料完成本地链路与真实提供方联调。各事件 `data` 为 JSON 对象；已知事件必要字段缺失、类型不符或 JSON 无效时标记前端本地协议错误 `STREAM_PROTOCOL_ERROR`，提示“回答数据异常，请重新生成”，保留已有内容，不展示来源或提交历史。已知事件和来源对象在必要字段有效时忽略额外字段；未知事件类型忽略，但不能以此推断成功。

| 事件 | 发送时机与草案数据 | 客户端行为 |
| --- | --- | --- |
| `status` | 阶段变化；必要字段 `stage` 为字符串，已知值为 `retrieving/generating/retrying` | 更新状态；`generating` 表示进入模型请求阶段，不保证模型已开始计算。合法但未知的阶段显示“正在处理”并继续等待。 |
| `delta` | 可多次发送；必要字段 `text` 为字符串 | 按顺序追加；空片段不视为正文。首字前空白按第 6.1 节暂存。 |
| `done` | 后端确认上游正常结束且回答非空白后发送；必要字段 `sources` 为数组，每项含字符串 `file_id`、`file_name`、`chunk_id` 和数字 `relevance_score` | 前端将合法 `done` 作为后端的正常结束声明，并检查已收到的回答非空白、`sources` 及其字段有效；全部通过后完成本轮并展示来源，纳入历史。`sources=[]` 有效；来源缺失、字段类型无效或累计回答为空白均为 `STREAM_PROTOCOL_ERROR`，不是成功。 |
| `incomplete` | 必要字段 `reason` 为字符串，已知值如 `length`、`empty` | 保留内容并标记未完成，无来源、不进历史；合法但未知的原因显示通用“回答未完成”并允许重新生成。 |
| `error` | 流已开始后可报告的错误，必要字段 `code`、`message` 为经清理的字符串 | 标记失败，无来源、不进历史。 |

示意：

```text
event: status
data: {"stage":"retrieving"}

event: status
data: {"stage":"generating"}

event: delta
data: {"text":"报销时需要"}

event: delta
data: {"text":"准备有效票据。"}

event: done
data: {"sources":[]}

```

正常情况下最多有一种终止事件（`done`、`incomplete` 或 `error`）。前端只接受当前请求的首个有效终态，之后的事件不得改变结果；切库时清空并使旧请求失效。处理尚未接受终态的 `done`、`incomplete`、`error`、EOF、中断或用户停止时，先核对用户侧 4 分钟实际期限：若已到期，即使超时定时器尚未执行，也判为超时；期限内已确认的终态不被迟到的回调改写。切库仍按既定规则清空旧会话。用户取消或网络直接断开时，不能依赖服务端成功发送终止事件。没有有效终止事件的 EOF，包括未完成帧，标记中断，不能判定成功。正常结束证据由后端检查；前端无法独立确认上游结束原因，只接受合法 `done` 作为该声明并核对非空白回答及来源字段。模型返回格式正确但未知的结束原因时后端发送通用 `incomplete`；上游流没有有效结束原因直接结束时按异常中断处理，不伪造 `done`。事件必须安全地序列化为 SSE 与 JSON；客户端应处理 UTF-8 多字节拆分、事件拆分/合并、不同换行和注释，不能将网络数据块直接当事件。

## 6. 已确认的重试、超时和取消

### 6.1 重试

流式模型请求在**尚未发送非空回答文字**时，遇到网络连接/超时、429 或 5xx 等暂时性错误，可按现有配置自动重试：默认最多两次，间隔 1 秒和 2 秒（含初次最多三次请求）。重试复用同次检索结果；SDK、后端、前端不得叠加隐式自动重试而超过约定。首个含非空白字符的回答文字前，纯空白暂存；出现有效文字后，将暂存空白和首段有效文字按原序合并为一个 `delta` 发送。空白判断使用与 ECMAScript `String.prototype.trim()` 一致的字符集合，原始文字不被裁剪；SQA-04 的后端判定已与本机 Node 对照，SQA-07 的前端校验使用 `trim()` 并在 Node 受控测试中验证，实际浏览器验证仍待进行。暂存期间发生可恢复错误可重试，但须丢弃失败尝试中尚未发送的暂存空白，避免混入新尝试；只有空白结束视为空回答。后端一旦向响应流发出非空文本 `delta` 即不再自动重试，不依赖浏览器是否已渲染；认证、配置、参数错误不自动重试，空回答和截断按未完成处理。自动重试应提示进度，耗尽后报告失败。

### 6.2 超时

一次问答整体上限初始为 **4 分钟**，从用户发送开始，包含前置检查、检索、重试和生成；阶段变化、保活和自动重试不重置。手动重新生成是新请求并重新计时。前端负责用户侧期限；后端从收到请求开始执行相应期限，两端起点和调度存在差异，不保证毫秒级一致。若期限到达，不再安排后续重试，保留内容并标记超时、不显示来源或纳入历史。统一代码为 `QUERY_TIMEOUT`：流前返回 HTTP 504 和既有 `{error:{code,message,details}}` JSON 外层；流内发送 `error` 事件的 `{code,message}`；前端本地期限到期也映射到同一超时状态。该代码已加入后端错误目录，前端流客户端已有期限，页面需在接入时从提交时刻传入或立即调用。现有 SDK `LLM_TIMEOUT=60` 是网络超时配置，不是整次问答的 60 秒上限；单独首字超时或文字停滞时限尚未确定。

### 6.3 取消及竞态

每次请求应具备独立取消能力及身份检查。主动停止、知识库切换、整体超时分别处理；应用内切换功能页不取消。已失效请求的迟到片段、终止事件、定时器和清理不得覆盖新请求。重试等待中取消后不再开始下一次尝试；检索返回后需检查是否已取消，避免继续发起不需要的模型调用。

前端中断连接、后端关闭上游流及停止处理均为尽力执行；同步工作线程中的阻塞操作不保证立即强制结束，也不保证外部服务立刻停止处理或计费。若已建立上游流，应在结束或取消时负责资源清理，并通过真实本地断连验证。

## 7. 实现建议及待确认事项

以下为建议，不将其记为已实施或已验证：

1. 将检索、上下文与来源准备抽成可复用部分；维持旧 API 和现有来源与上下文限制的差异。流式模型调用和 SSE 组装保持清楚边界。
2. 避免在异步事件循环中直接执行阻塞检索、同步 SDK 迭代或 `time.sleep()`；可考虑隔离同步检索、采用可取消的模型流及重试等待。Python 最低支持 3.10；依赖采用最低版本约束而非锁定，异步 SDK、取消和关闭方法需在实际支持环境验证。
3. 关键词索引和模型加载涉及共享状态；线程隔离本身不证明并发安全。验证同时请求、索引更新及取消，不擅自修改现有数据。
4. 建议用稳定轮次标识管理可见记录，并从已完成轮次派生最近 20 条模型历史；草稿、请求标识、取消控制器和计时器分开。状态管理具体结构仍待实现设计。
5. 事件字段和错误代码按第 5、6 节执行；实现时验证保活、前后端截止时间配置、SDK 关闭及取消传播。未经验证的细节不得表述为已有实现。

### 7.1 实施中需要验证的细节

- 按第 3–6 节实现已确认的替换时点、终态、空白、协议错误、超时和历史规则；用受控事件与计时器验证处理顺序和竞态。
- 已在 SQA-04 将后端空白字符判定对齐 ECMAScript `trim()`，需在前端任务和实际浏览器中继续验证一致性。仍需结合实际依赖验证上游资源关闭 API、保活和定时器实现；这些实现细节不得改变已确认的界面与数据语义。
- 当前非流式实现将 `LLM_MAX_RETRIES` 限制在 0–2 次，默认值为 2；流式方案沿用该范围，因此初次请求加重试最多三次。检查底层 SDK 与应用层不叠加重试。

## 8. 验收标准

以下均是本功能未来验收条件，不代表本次已执行：

| ID | 验收条件 |
| --- | --- |
| AC-01 | 正常回答在 `done` 前逐段可见；仅合法正常完成后展示来源并加入历史。 |
| AC-02 | 空库返回流前错误、不调用模型；无匹配时继续模型并正常返回空来源。 |
| AC-03 | 首字前和首字后停止、失败、超时、截断或空回答均按第 3 节保留/标记，不展示来源、不加入历史。 |
| AC-04 | 最新未完成轮重新生成时立即清除旧答案；新请求首字前失败/停止/超时不恢复；有效新问题提交后旧轮不可重试，校验不通过不创建新轮；草稿不丢失、不误发送。 |
| AC-05 | 显示整个当前会话；按时间顺序从已完成轮次取最近 20 条消息，当前问题单独传入；刷新和切库清空。 |
| AC-06 | 切库取消并隔离旧事件；应用内切页继续生成，返回时显示准确状态；滚动行为符合第 3.3 节。 |
| AC-07 | 参数无效、库不存在、空库在流前返回预期 HTTP/JSON；流后检索/模型失败发送 `error`；无终止事件断流标记中断。整体超时在流前为 HTTP 504 的 `QUERY_TIMEOUT`，流内为同码 `error`，前端本地计时映射同一超时状态。 |
| AC-08 | 默认重试上限和 1/2 秒间隔正确；不超过三次模型请求；首个有效文字前暂存纯空白，失败重试时丢弃该次暂存，首段有效文字与暂存按原序作为一个 `delta` 发送，发出非空文字后不重试；复用一次检索，认证/配置/参数错误不重试。 |
| AC-09 | 总计时不因状态、保活或自动重试重置；4 分钟到达后标记超时且停止安排重试；手动重新生成开始新计时。 |
| AC-10 | 停止、切库、超时与事件竞态只接受当前请求有效终态；无已确认终态时期限后处理完成、未完成、失败、中断或停止均判超时，期限内已确认的终态不被迟到回调改写；切库仍清空旧会话，旧事件及清理不影响新请求；上游流按可验证边界关闭。 |
| AC-11 | UTF-8 字符跨块、事件拆分和合并、换行、注释与提前 EOF 不丢字、乱码或误判成功；已知事件非法数据及空白回答后收到 `done` 均为 `STREAM_PROTOCOL_ERROR`，额外字段和未知事件忽略，合法未知阶段/未完成原因显示通用状态；无有效终止事件不能成功。 |
| AC-12 | 原 JSON 接口和相关回归保持现有行为，包括既有空回答行为；检索、来源与模型输入合同不被无意改变。 |
| AC-13 | 模拟测试、真实本地流式 HTTP 与可控上游测试、真实 DeepSeek 联调分别记录证据和限制；不把 TestClient/模拟结果称为真实端到端。 |

真实本地流测试需覆盖首段及时到达、断连传播、可控阻塞检索返回后的取消、重试等待取消、资源关闭和并发；真实服务联调受环境、凭据与网络条件约束。文档记录及模拟通过不等于真实链路通过。
