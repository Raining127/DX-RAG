# 让问答区适应屏幕，而不是让用户寻找输入框

Task reference：TUI01；记录日期：2026-09-30。独立前端展示优化，沿用现有业务状态与 API，不归入检索实验 Phase。

## 页面外壳与对话区的职责

`Home` 管理导航、知识库共享状态，以及上传与文件列表联动。本次新增状态只控制窄屏与菜单开关；`selectedKey` 仍决定显示哪个功能。四个组件继续挂载，通过 `hidden` 切换显示，所以返回问答时，草稿与历史不会因卸载而丢失。

`QAPanel` 管理问答请求与会话。请求字段、history 截断和 requestVersion 检查保持原样；本次改变可用空间、来源样式与滚动范围，没有将导航状态带入 API。新增 `WorkspaceIcon` 用 SVG 路径提供统一图标，没有增加依赖。

## Flex 高度分配为什么需要 min-height: 0

问答页面使用 `calc(100dvh - 页头高度)`。`dvh` 随浏览器可用视口变化；页头、知识库工具条和输入区占用自身高度，其余空间分配给对话区。

```text
视口 → 页头 → 页面标题 → 问答面板
                          ├─ 工具条：固定自身高度
                          ├─ 对话区：剩余空间，内部滚动
                          └─ 输入区：不收缩
```

Flex 子项默认的最小尺寸可能由内容决定。仅写 `flex: 1`，长答案仍可能撑高父容器；在内容容器、功能容器和对话区使用 `min-height: 0`，才允许缩到分配的空间，由 `overflow-y: auto` 接管滚动。长链接使用 `overflow-wrap: anywhere`；代码块保留自己的横向滚动，不撑宽整个页面。

## 自动滚动属于哪个容器

原来的末尾元素 `scrollIntoView` 可能同时移动外层页面。本次把 ref 绑定到对话容器，仅调用该容器的 `scrollTo`。历史、待回答问题和请求状态变化仍触发滚动；减少动态效果偏好使用 `auto`，其余使用 `smooth`。这是展示副作用，不改变历史提交与请求竞态保护。

## 来源与窄屏导航

来源继续以 `chunk_id` 作为 React key，文件名只用于展示。相关性保留三位小数，没有转成百分比或称作置信度；展开来源不代表新增引用验证能力。

桌面使用 Sider，breakpoint 回调更新窄屏状态；窄屏使用明确的菜单按钮和现有 Drawer。选择入口关闭 Drawer，不卸载功能页面。复用现有组件减少自定义遮罩、关闭和键盘行为的成本。本次验证导航与 Escape，没有声称完整无障碍审计。

## 实际遇到的问题

- 跨盘 node_modules junction 导致 Next.js 入口路径解析错误。复制现有依赖到 worktree 后解决，没有改版本。
- 原组件测试 VM 缺少 `process`。新增公开演示标记后，仅补入空的 `process.env`；业务断言保留。
- Ant Design 两字按钮含自动插入的空格，Select 的可点击面也不是内部只读 input。测试按实际控件定位，避免强制点击。
- 折叠后的 Sider 已不可见；测试 breakpoint 状态需要检查 DOM attachment。这是定位修复，布局断言仍保留。

浏览器使用内存演示 API，并用受控 fixture 验证错误与长内容；它证明前端交互保持，不证明真实检索、模型质量、OCR 或上传解析。运行性能、跨浏览器表现和真实手机软键盘未测量。演示脚本仅用于本地预览。
